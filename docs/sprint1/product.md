# СтейНау — Sprint 1

> **Статус документа:** в роботі.  
> Частина розділів заповнюється Керівником тестування.  
> Таблиці елементів BPMN підготовлені Тест-аналітиком на основі офіційної картки П4 «СтейНау» і можуть використовуватись Інженером з тестування як специфікація для побудови діаграм.

### 2. Користувачі та ролі

Офіційні ролі продукту:

- Менеджер.

Зовнішні учасники:
- Платіжний провайдер;
- Служба прибирання.

**Статус:** ⏳ потребує оформлення в `product.md`

---

### 3. Ключові бізнес-процеси

За карткою П4 для моделювання визначено 4 процеси:

1. Бронювання номера.
2. Заселення і виселення.
3. Скасування і повернення коштів.
4. Обробка повідомлень гостей.

Для кожного процесу нижче наведено текстову таблицю елементів BPMN у форматі «крок — тип — опис».

**Статус:** ✅ таблиці елементів підготовлені Тест-аналітиком  
**Графічні BPMN-моделі:** ⏳ ще мають бути побудовані Інженером з тестування

---

### 4. Замовлення на нову функцію

**Нова функція:** «Сезонні тарифи та політика скасування».

Очікування замовника:
1. Вартість проживання рахується за ніч із сезонним коефіцієнтом.
2. Ночі напередодні вихідних коштують дорожче на фіксований відсоток.
3. За тривале проживання діє знижка на підсумок.
4. Гість бачить розрахунок вартості за ночами до підтвердження бронювання.
5. Політика скасування залежить від кількості днів до заїзду і показується до підтвердження.
6. Менеджер налаштовує сезони і коефіцієнти без участі розробників.

**Статус:** ✅ очікування визначені за карткою П4  
**Беклог User Stories:** ✅ оформлено окремо у `backlog.md`

## Процеси та таблиці елементів BPMN

Наведені таблиці підготовлені Тест-аналітиком до побудови BPMN-моделей і слугують текстовою специфікацією для Інженера з тестування.

---

### Процес 1 — Бронювання номера

**Учасники:**
- Гість
- Готель
  - Система
  - Адміністратор

**Тригер:** гість обрав номер і натиснув «Бронювати».

**Кінцеві результати:**
- «Підтверджено»
- «Дані некоректні»
- «Номер зайнятий»

| № | Крок | Тип BPMN | Опис |
|---|---|---|---|
| 1 | Гість обрав номер і натиснув «Бронювати» | Start Event | Початок процесу бронювання номера. |
| 2 | Ввести дані бронювання | User Task | Гість вводить дати заїзду і виїзду, ім'я, прізвище, email і телефон. |
| 3 | Перевірити формат полів | Service Task | Система перевіряє правильність введених даних. |
| 4 | Дані коректні? | Exclusive Gateway (XOR) | Розгалуження за результатом перевірки введених даних. |
| 5 | Завершити з результатом «Дані некоректні» | End Event | Процес завершується, якщо дані не пройшли валідацію. |
| 6 | Перевірити доступність номера | Service Task | Якщо дані коректні, система перевіряє, чи номер вільний на вибрані дати. |
| 7 | Номер вільний? | Exclusive Gateway (XOR) | Розгалуження залежно від доступності номера. |
| 8 | Завершити з результатом «Номер зайнятий» | End Event | Процес завершується, якщо номер уже зайнятий на вибраний період. |
| 9 | Розрахувати вартість | Service Task | Якщо номер вільний, система розраховує вартість проживання. |
| 10 | Створити бронювання | Service Task | Система створює бронювання на вибраний період. |
| 11 | Надіслати підтвердження гостю | Send Task | Система надсилає гостю підтвердження створення бронювання. |
| 12 | Переглянути бронювання в панелі | User Task | Адміністратор бачить створене бронювання в адмінпанелі. |
| 13 | Бронювання підтверджено | End Event | Процес успішно завершується зі статусом «Підтверджено». |

### Процес 2 — Заселення і виселення

**Учасники:**
- Гість
- Готель
  - Адміністратор
  - Менеджер
- Служба прибирання

**Тригер:** настав день заїзду.

**Кінцеві результати:**
- «Виселено»
- «Гість не з'явився»

| № | Крок | Тип BPMN | Опис |
|---|---|---|---|
| 1 | Настав день заїзду | Timer Start Event | Процес запускається у день запланованого заїзду гостя. |
| 2 | Знайти бронювання | User Task | Адміністратор знаходить бронювання гостя. |
| 3 | Перевірити документ гостя | User Task | Адміністратор перевіряє документ гостя. |
| 4 | Гість прибув? | Exclusive Gateway (XOR) | Визначається, чи з'явився гість для заселення. |
| 5 | Очікувати гостя до моменту неявки | Intermediate Timer Event | Якщо гість не прибув, очікується встановлений час до фіксації неявки. |
| 6 | Гість не з'явився | End Event | Процес завершується результатом «Гість не з'явився». |
| 7 | Видати ключ | User Task | Якщо гість прибув, адміністратор видає ключ від номера. |
| 8 | Встановити статус «Заселено» | User Task | Адміністратор фіксує факт заселення гостя. |
| 9 | Очікувати дня виїзду | Intermediate Timer Event | Проживання триває до запланованого дня виїзду. |
| 10 | Перевірити номер при виїзді | User Task | Після завершення проживання номер перевіряється. |
| 11 | Розрахувати додаткові послуги | User Task | Готель визначає вартість додаткових послуг гостя. |
| 12 | Розпочати завершення проживання | Parallel Gateway (AND) | Після виїзду паралельно виконуються завершальні дії. |
| 13 | Закрити бронювання | User Task | Готель закриває бронювання гостя. |
| 14 | Передати номер службі прибирання | Send Task | Готель передає інформацію про номер службі прибирання. |
| 15 | Прийняти номер для прибирання | Receive Task | Служба прибирання отримує інформацію про необхідність прибирання номера. |
| 16 | Прибрати номер | Manual Task | Служба прибирання виконує прибирання номера. |
| 17 | Завершити паралельні дії | Parallel Gateway (AND) | Процес продовжується після завершення закриття бронювання та прибирання. |
| 18 | Зробити номер доступним | Task | Після завершення прибирання номер знову стає доступним. |
| 19 | Гостя виселено | End Event | Процес завершується результатом «Виселено». |

### Процес 3 — Скасування і повернення коштів

**Учасники:**
- Гість
- Готель
  - Система
  - Менеджер
- Платіжний провайдер

**Тригер:** гість запросив скасування.

**Кінцеві результати:**
- «Скасовано, кошти повернуто»
- «Скасовано без повернення»
- «Гість передумав»

| № | Крок | Тип BPMN | Опис |
|---|---|---|---|
| 1 | Гість запросив скасування | Start Event | Процес починається після запиту гостя на скасування бронювання. |
| 2 | Визначити кількість днів до заїзду | Service Task | Система визначає кількість днів, що залишилися до дати заїзду. |
| 3 | Визначити рівень штрафу | Exclusive Gateway (XOR) | Політика скасування розділяється на три варіанти: без штрафу, частковий штраф або повний штраф. |
| 4 | Розрахувати скасування без штрафу | Service Task | Система визначає повну суму до повернення. |
| 5 | Розрахувати частковий штраф | Service Task | Система визначає частину вартості, що утримується, та суму повернення. |
| 6 | Розрахувати повний штраф | Service Task | Система визначає, що кошти не повертаються. |
| 7 | Показати суму до повернення | Service Task | Гість бачить фінансовий результат скасування. |
| 8 | Підтвердити скасування? | Exclusive Gateway (XOR) | Гість вирішує, чи продовжувати операцію скасування. |
| 9 | Відмовитися від скасування | User Task | Гість не підтверджує операцію. |
| 10 | Гість передумав | End Event | Процес завершується без скасування бронювання. |
| 11 | Підтвердити скасування | User Task | Гість підтверджує скасування бронювання. |
| 12 | Звільнити номер | Service Task | Система робить номер доступним для наступних бронювань. |
| 13 | Потрібне повернення коштів? | Exclusive Gateway (XOR) | Визначається, чи є сума для повернення гостю. |
| 14 | Ініціювати повернення | User Task | Якщо повернення передбачене, менеджер ініціює його через платіжного провайдера. |
| 15 | Надіслати запит платіжному провайдеру | Send Task | Готель передає провайдеру запит на повернення коштів. |
| 16 | Обробити повернення коштів | Service Task | Платіжний провайдер виконує операцію повернення. |
| 17 | Отримати результат повернення | Receive Task | Готель отримує результат операції від платіжного провайдера. |
| 18 | Надіслати повідомлення гостю | Send Task | Гість отримує інформацію про результат скасування. |
| 19 | Скасовано, кошти повернуто | End Event | Процес завершується з поверненням коштів. |
| 20 | Скасовано без повернення | End Event | При повному штрафі процес завершується без повернення коштів. |

**Примітка:**  
У SRS існує суперечність щодо межі безкоштовного скасування: F-110 вказує 5 і більше днів, а BL-60 — 7 і більше днів. До уточнення вимог BPMN має відображати три рівні штрафу без самостійного усунення цієї суперечності.

### Процес 4 — Обробка повідомлень гостей

**Учасники:**
- Гість
- Готель
  - Система
  - Адміністратор
  - Менеджер

**Тригер:** надіслано контактну форму з ім'ям, email, телефоном, темою та повідомленням.

**Кінцевий результат:**
- «Оброблено»

| № | Крок | Тип BPMN | Опис |
|---|---|---|---|
| 1 | Надіслано контактну форму | Message Start Event | Процес починається після надсилання гостем контактної форми. |
| 2 | Зберегти повідомлення | Service Task | Система зберігає отримане повідомлення гостя. |
| 3 | Переглянути повідомлення | User Task | Адміністратор читає повідомлення в адмінпанелі. |
| 4 | Визначити тип питання | Exclusive Gateway (XOR) | Адміністратор визначає категорію звернення. |
| 5 | Передати питання менеджеру | User Task | Якщо звернення стосується ціни або повернення коштів, адміністратор передає його менеджеру. |
| 6 | Обробити питання адміністратором | User Task | Інші звернення адміністратор обробляє самостійно. |
| 7 | Підготувати відповідь | User Task | Відповідальний виконавець формує відповідь гостю. |
| 8 | Надіслати відповідь на email | Send Task | Відповідь надсилається гостю електронною поштою. |
| 9 | Відповідь надана вчасно? | Event-Based Gateway | Процес очікує завершення відповіді або настання 24-годинного таймера. |
| 10 | Минуло 24 години без відповіді | Intermediate Timer Event | Якщо відповідь не надана протягом 24 годин, спрацьовує нагадування. |
| 11 | Надіслати нагадування | Service Task | Система нагадує відповідальному виконавцю про необроблене звернення. |
| 12 | Позначити повідомлення обробленим або видалити | User Task | Після відповіді повідомлення позначається як оброблене або видаляється. |
| 13 | Повідомлення оброблено | End Event | Процес завершується результатом «Оброблено». |
