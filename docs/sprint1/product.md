# СтейНау — Sprint 1

> **Статус документа:** готово (очікує на побудову графічних моделей та внутрішнє рецензування).
> Текстова частина заповнена Керівником тестування та Тест-аналітиком.

## Структура документа

### 1. Характеристика продукту

- **Профіль компанії:** «СтейНау» — одеська ІТ-компанія, заснована у 2020 році, яка обслуговує близько 120 закладів у південних областях.
- **Опис продукту:** Власна система онлайн-бронювання без посередників, розроблена спеціально для малих готелів та гостьових будинків (місткістю до 30 номерів). Технологічний стек: вебзастосунок із гостьовою частиною на React, серверними сервісами на Java (Spring Boot) та СУБД PostgreSQL.
- **Контекст використання:** Команда розробки налічує 18 осіб. Відділ забезпечення якості створено щойно, реагуючи на проблеми минулого літнього сезону, коли трапилося кілька інцидентів із подвійними бронюваннями номерів.
- **Основна цінність продукту:** Забезпечення готелів надійним та незалежним інструментом для прямих бронювань, що усуває потребу в ручному обліку та сторонніх агрегаторах.
- **Стратегічний напрям:** Перехід на гнучке ціноутворення за сезонами та прозору політику скасування, оскільки зараз готелі ведуть ці розрахунки у таблицях вручну.

**Статус:** ✅ готово

---

### 2. Користувачі та ролі

Офіційні ролі продукту:
- **Гість:** переглядає опис готелю та номери з цінами, бронює номер, звертається через контактну форму.
- **Адміністратор готелю:** веде номери (додає тип, ціну, зручності, доступність), читає повідомлення гостей, переглядає звіти, налаштовує брендинг.
- **Менеджер:** встановлює тарифи та політику скасування, схвалює повернення коштів, контролює заселення (в системі використовує адмінпанель).

Зовнішні учасники:
- **Платіжний провайдер:** обробляє транзакції та повернення коштів.
- **Служба прибирання:** отримує сповіщення про необхідність прибирання після виселення гостя.

**Статус:** ✅ готово

---

### 3. Ключові бізнес-процеси

За карткою П4 для моделювання визначено 4 процеси:

1. Бронювання номера.
2. Заселення і виселення.
3. Скасування і повернення коштів.
4. Обробка повідомлень гостей.

Для кожного процесу нижче наведено текстову таблицю елементів BPMN у форматі «крок — тип — опис».

**Статус:** ✅ таблиці елементів підготовлені Тест-аналітиком  
**Графічні BPMN-моделі:** ⏳ створені Інженером з тестування, очікують на внутрішнє рецензування.

---

### 4. Замовлення на нову функцію

**Нова функція:** «Сезонні тарифи та політика скасування».

Очікування замовника:
1. Вартість проживання рахується за ніч із сезонним коефіцієнтом.
2. Ночі напередодні вихідних коштують дорожче на фіксований відсоток.
3. За тривале проживання діє знижка на підсумок.
4. Гість бачить розрахунок вартості за ночами до підтвердження бронювання.
5. Політика скасування залежить від кількості днів до заїзду і показується до підтвердження.
6. Менеджер налаштовує сезони і коефіцієнти без участі розробників.

**Статус:** ✅ очікування визначені за карткою П4  
**Беклог User Stories:** ✅ оформлено окремо у `backlog.md`

## Процеси та таблиці елементів BPMN

Наведені таблиці підготовлені Тест-аналітиком до побудови BPMN-моделей і слугують текстовою специфікацією для Інженера з тестування.

### Процес 1 — Бронювання номера

**Учасники:**
- Гість
- Готель
  - Система
  - Адміністратор

**Тригер:** гість обрав номер і натиснув «Бронювати».

**Кінцеві результати:**
- «Підтверджено»
- «Дані некоректні»
- «Номер зайнятий»

| № | Пул / доріжка | Крок | Тип BPMN | Опис |
|---|---|---|---|---|
| 1 | Гість | Обрати номер і натиснути «Бронювати» | Start Event | Процес починається після того, як гість обрав номер і ініціював бронювання. |
| 2 | Гість | Ввести дані бронювання | User Task | Гість вводить дати заїзду і виїзду, ім'я, прізвище, email і телефон. |
| 3 | Готель / Система | Перевірити формат полів | Service Task | Система перевіряє правильність введених даних. |
| 4 | Готель / Система | Дані коректні? | Exclusive Gateway (XOR) | Розгалуження за результатом валідації введених даних. |
| 5 | Готель / Система | Завершити з результатом «Дані некоректні» | End Event | Процес завершується, якщо дані не пройшли перевірку. |
| 6 | Готель / Система | Перевірити доступність номера | Service Task | Якщо дані коректні, система перевіряє, чи номер вільний на вибрані дати. |
| 7 | Готель / Система | Номер вільний? | Exclusive Gateway (XOR) | Розгалуження залежно від доступності номера. |
| 8 | Готель / Система | Завершити з результатом «Номер зайнятий» | End Event | Процес завершується, якщо номер зайнятий на вибраний період. |
| 9 | Готель / Система | Розрахувати вартість | Service Task | Якщо номер вільний, система розраховує вартість проживання. |
| 10 | Готель / Система | Створити бронювання | Service Task | Система створює бронювання на вибраний період. |
| 11 | Готель / Система | Надіслати підтвердження гостю | Send Task | Система надсилає гостю підтвердження бронювання. |
| 12 | Готель / Адміністратор | Переглянути бронювання в панелі | User Task | Адміністратор бачить нове бронювання в адмінпанелі. |
| 13 | Готель / Система | Бронювання підтверджено | End Event | Процес успішно завершується зі статусом «Підтверджено». |

### Процес 2 — Заселення і виселення

**Учасники:**
- Гість
- Готель
  - Адміністратор
  - Менеджер
- Служба прибирання

**Тригер:** настав день заїзду.

**Кінцеві результати:**
- «Виселено»
- «Гість не з'явився»

| № | Пул / доріжка | Крок | Тип BPMN | Опис |
|---|---|---|---|---|
| 1 | Готель / Адміністратор | Настав день заїзду | Timer Start Event | Процес запускається у день запланованого заїзду гостя. |
| 2 | Готель / Адміністратор | Очікувати прибуття гостя | Intermediate Catch Event | Адміністратор очікує прибуття гостя для заселення. |
| 3 | Готель / Адміністратор | Гість прибув? | Exclusive Gateway (XOR) | Перевіряється, чи прибув гість у встановлений час. |
| 4 | Готель / Адміністратор | Очікувати до моменту неявки | Intermediate Timer Event | Якщо гість ще не прибув, очікування триває до граничного часу неявки. |
| 5 | Готель / Адміністратор | Гість не з'явився | End Event | Процес завершується результатом «Гість не з'явився». |
| 6 | Готель / Адміністратор | Знайти бронювання | User Task | Якщо гість прибув, адміністратор знаходить його бронювання. |
| 7 | Готель / Адміністратор | Перевірити документ гостя | User Task | Адміністратор перевіряє документ гостя. |
| 8 | Готель / Адміністратор | Видати ключ | User Task | Адміністратор видає гостю ключ від номера. |
| 9 | Готель / Адміністратор | Встановити статус «Заселено» | User Task | Адміністратор фіксує факт заселення. |
| 10 | Готель / Адміністратор | Очікувати дня виїзду | Intermediate Timer Event | Проживання триває до запланованого дня виїзду. |
| 11 | Готель / Адміністратор | Перевірити номер при виїзді | User Task | Після завершення проживання номер перевіряється. |
| 12 | Готель / Менеджер | Розрахувати додаткові послуги | User Task | Визначається вартість додаткових послуг гостя. |
| 13 | Готель | Розпочати завершальні дії | Parallel Gateway (AND) | Паралельно запускаються закриття бронювання та передача номера на прибирання. |
| 14 | Готель / Адміністратор | Закрити бронювання | User Task | Адміністратор закриває бронювання гостя. |
| 15 | Готель / Адміністратор | Передати номер службі прибирання | Send Task | Готель передає повідомлення про необхідність прибирання номера. |
| 16 | Служба прибирання | Отримати завдання на прибирання | Receive Task | Служба прибирання отримує завдання. |
| 17 | Служба прибирання | Прибрати номер | Manual Task | Служба прибирання виконує прибирання номера. |
| 18 | Готель | Завершити паралельні дії | Parallel Gateway (AND) | Процес продовжується після завершення обох паралельних гілок. |
| 19 | Готель / Система | Зробити номер доступним | Service Task | Після завершення прибирання номер знову стає доступним для бронювання. |
| 20 | Готель | Гостя виселено | End Event | Процес завершується результатом «Виселено». |

### Процес 3 — Скасування і повернення коштів

**Учасники:**
- Гість
- Готель
  - Система
  - Менеджер
- Платіжний провайдер

**Тригер:** гість запросив скасування.

**Кінцеві результати:**
- «Скасовано, кошти повернуто»
- «Скасовано без повернення»
- «Гість передумав»

| № | Пул / доріжка | Крок | Тип BPMN | Опис |
|---|---|---|---|---|
| 1 | Гість | Запросити скасування | Start Event | Процес починається після запиту гостя на скасування бронювання. |
| 2 | Готель / Система | Визначити кількість днів до заїзду | Service Task | Система визначає, скільки днів залишилося до дати заїзду. |
| 3 | Готель / Система | Визначити рівень штрафу | Exclusive Gateway (XOR) | Політика скасування розділяється на три варіанти: без штрафу, частковий штраф або повний штраф. |
| 4 | Готель / Система | Розрахувати скасування без штрафу | Service Task | Система визначає повну суму до повернення. |
| 5 | Готель / Система | Розрахувати частковий штраф | Service Task | Система визначає суму утримання та суму повернення. |
| 6 | Готель / Система | Розрахувати повний штраф | Service Task | Система визначає, що кошти не повертаються. |
| 7 | Готель / Система | Показати суму до повернення | Service Task | Гість отримує інформацію про фінансовий результат скасування. |
| 8 | Гість | Підтвердити скасування? | Exclusive Gateway (XOR) | Гість вирішує, чи продовжувати операцію. |
| 9 | Гість | Відмовитися від скасування | User Task | Гість вирішує не скасовувати бронювання. |
| 10 | Гість | Гість передумав | End Event | Процес завершується без скасування бронювання. |
| 11 | Гість | Підтвердити скасування | User Task | Гість підтверджує скасування бронювання. |
| 12 | Готель / Система | Звільнити номер | Service Task | Система робить номер доступним для наступних бронювань. |
| 13 | Готель / Система | Потрібне повернення коштів? | Exclusive Gateway (XOR) | Визначається, чи є сума, яку потрібно повернути гостю. |
| 14 | Готель / Менеджер | Ініціювати повернення | User Task | Якщо повернення передбачене, менеджер ініціює його через платіжного провайдера. |
| 15 | Готель / Менеджер | Надіслати запит платіжному провайдеру | Send Task | Готель передає провайдеру запит на повернення коштів. |
| 16 | Платіжний провайдер | Обробити повернення коштів | Service Task | Платіжний провайдер виконує операцію повернення. |
| 17 | Готель / Менеджер | Отримати результат повернення | Receive Task | Готель отримує результат операції від платіжного провайдера. |
| 18 | Готель / Система | Надіслати повідомлення гостю | Send Task | Система повідомляє гостя про результат скасування. |
| 19 | Гість | Скасовано, кошти повернуто | End Event | Процес завершується з поверненням коштів. |
| 20 | Гість | Скасовано без повернення | End Event | При повному штрафі процес завершується без повернення коштів. |

**Примітка:**  
У SRS існує суперечність щодо межі безкоштовного скасування: F-110 вказує 5 і більше днів, а BL-60 — 7 і більше днів. До уточнення вимог BPMN має відображати три рівні штрафу без самостійного усунення цієї суперечності.

### Процес 4 — Обробка повідомлень гостей

**Учасники:**
- Гість
- Готель
  - Система
  - Адміністратор
  - Менеджер

**Тригер:** надіслано контактну форму з ім'ям, email, телефоном, темою та повідомленням.

**Кінцевий результат:**
- «Оброблено»

| № | Пул / доріжка | Крок | Тип BPMN | Опис |
|---|---|---|---|---|
| 1 | Гість | Надіслати контактну форму | Message Start Event | Процес починається після надсилання гостем контактної форми. |
| 2 | Готель / Система | Зберегти повідомлення | Service Task | Система зберігає отримане повідомлення гостя. |
| 3 | Готель / Адміністратор | Переглянути повідомлення | User Task | Адміністратор читає повідомлення в адмінпанелі. |
| 4 | Готель / Адміністратор | Визначити тип питання | Exclusive Gateway (XOR) | Адміністратор визначає категорію звернення. |
| 5 | Готель / Адміністратор | Передати питання менеджеру | User Task | Якщо звернення стосується ціни або повернення коштів, адміністратор передає його менеджеру. |
| 6 | Готель / Адміністратор | Обробити питання адміністратором | User Task | Інші звернення адміністратор обробляє самостійно. |
| 7 | Готель / Менеджер або Адміністратор | Підготувати відповідь | User Task | Відповідальний виконавець формує відповідь гостю. |
| 8 | Готель / Менеджер або Адміністратор | Надіслати відповідь на email | Send Task | Відповідь надсилається гостю електронною поштою. |
| 9 | Готель / Система | Відповідь надана вчасно? | Event-Based Gateway | Процес очікує або факту відповіді, або спливу 24 годин. |
| 10 | Готель / Система | Минуло 24 години без відповіді | Intermediate Timer Event | Якщо відповідь не надана протягом 24 годин, спрацьовує таймер. |
| 11 | Готель / Система | Надіслати нагадування | Service Task | Система нагадує відповідальному виконавцю про необроблене звернення. |
| 12 | Готель / Адміністратор | Позначити повідомлення обробленим або видалити | User Task | Після відповіді повідомлення позначається як оброблене або видаляється. |
| 13 | Готель | Повідомлення оброблено | End Event | Процес завершується результатом «Оброблено». |
