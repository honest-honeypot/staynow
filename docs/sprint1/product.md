## Структура документа

### 1. Характеристика продукту

- **Профіль компанії:** «СтейНау» — одеська ІТ-компанія, заснована у 2020 році, яка обслуговує близько 120 закладів у південних областях.
- **Опис продукту:** Власна система онлайн-бронювання без посередників, розроблена спеціально для малих готелів та гостьових будинків (місткістю до 30 номерів). Технологічний стек: вебзастосунок із гостьовою частиною на React, серверними сервісами на Java (Spring Boot) та СУБД PostgreSQL.
- **Контекст використання:** Команда розробки налічує 18 осіб. Відділ забезпечення якості створено щойно, реагуючи на проблеми минулого літнього сезону, коли трапилося кілька інцидентів із подвійними бронюваннями номерів.
- **Основна цінність продукту:** Забезпечення готелів надійним та незалежним інструментом для прямих бронювань, що усуває потребу в ручному обліку та сторонніх агрегаторах.
- **Стратегічний напрям:** Перехід на гнучке ціноутворення за сезонами та прозору політику скасування, оскільки зараз готелі ведуть ці розрахунки у таблицях вручну.

**Статус:** ✅ готово

### 2. Користувачі та ролі

Офіційні ролі продукту:
- **Гість:** переглядає опис готелю та номери з цінами, бронює номер, звертається через контактну форму.
- **Адміністратор готелю:** веде номери (додає тип, ціну, зручності, доступність), читає повідомлення гостей, переглядає звіти, налаштовує брендинг.
- **Менеджер:** встановлює тарифи та політику скасування, схвалює повернення коштів, контролює заселення (в системі використовує адмінпанель).

Зовнішні учасники:
- **Платіжний провайдер:** обробляє транзакції та повернення коштів.
- **Служба прибирання:** отримує сповіщення про необхідність прибирання після виселення гостя.

Автоматичні кроки продукту:
- **Система:** виконує валідацію, перевірку доступності, розрахунки й розсилання повідомлень без участі людини; у моделях виділена окремою доріжкою.

### 4. Замовлення на нову функцію

**Нова функція:** «Сезонні тарифи та політика скасування».

Очікування замовника:
1. Вартість проживання рахується за ніч із сезонним коефіцієнтом.
2. Ночі напередодні вихідних коштують дорожче на фіксований відсоток.
3. За тривале проживання діє знижка на підсумок.
4. Гість бачить розрахунок вартості за ночами до підтвердження бронювання.
5. Політика скасування залежить від кількості днів до заїзду і показується до підтвердження.
6. Менеджер налаштовує сезони і коефіцієнти без участі розробників.

**Статус:** ✅ очікування визначені за карткою П4  
**Беклог User Stories:** ✅ оформлено окремо у `backlog.md`

### Процес 3 — Скасування і повернення коштів

**Учасники:**
- Гість
- Готель
  - Система
  - Менеджер
- Платіжний провайдер

**Тригер:** гість запросив скасування.

**Кінцеві результати:**
- «Скасовано, кошти повернуто»
- «Скасовано без повернення»
- «Гість передумав»

| № | Пул / доріжка | Крок | Тип BPMN | Опис |
|---|---|---|---|---|
| 1 | Гість | Виникла потреба скасувати бронювання | Start Event | Початкова подія пулу «Гість». |
| 2 | Готель / Система | Визначити кількість днів до заїзду | Service Task | Система визначає, скільки днів залишилося до дати заїзду. |
| 3 | Готель / Система | Визначити рівень штрафу | Exclusive Gateway (XOR) | Політика скасування розділяється на три варіанти: без штрафу, частковий штраф або повний штраф. |
| 4 | Готель / Система | Розрахувати скасування без штрафу | Service Task | Система визначає повну суму до повернення. |
| 5 | Готель / Система | Розрахувати частковий штраф | Service Task | Система визначає суму утримання та суму повернення. |
| 6 | Готель / Система | Розрахувати повний штраф | Service Task | Система визначає, що кошти не повертаються. |
| 7 | Готель / Система | Показати суму до повернення | Send Task | Надсилає гостю розрахунок скасування (потік 27) до кроку 21. |
| 8 | Гість | Підтвердити скасування? | Exclusive Gateway (XOR) | Гість вирішує, чи продовжувати операцію. |
| 9 | Гість | Відмовитися від скасування | User Task | Гість вирішує не скасовувати бронювання. |
| 10 | Гість | Гість передумав | End Event | Процес завершується без скасування бронювання. |
| 11 | Гість | Підтвердити скасування | User Task | Гість підтверджує скасування бронювання. |
| 12 | Готель / Система | Звільнити номер | Service Task | Система робить номер доступним для наступних бронювань. |
| 13 | Готель / Система | Потрібне повернення коштів? | Exclusive Gateway (XOR) | Визначається, чи є сума, яку потрібно повернути гостю. |
| 14 | Готель / Менеджер | Ініціювати повернення | User Task | Якщо повернення передбачене, менеджер ініціює його через платіжного провайдера. |
| 15 | Готель / Менеджер | Надіслати запит платіжному провайдеру | Send Task | Готель передає провайдеру запит на повернення коштів. |
| 16 | Платіжний провайдер | Обробити повернення коштів | Service Task | Платіжний провайдер виконує операцію повернення. |
| 17 | Готель / Менеджер | Отримати результат повернення | Receive Task | Готель отримує результат операції від платіжного провайдера. |
| 18 | Готель / Система | Надіслати повідомлення гостю | Send Task | Надсилає гостю результат скасування (потік 31) до кроку 22. |
| 19 | Гість | Скасовано, кошти повернуто | End Event | Процес завершується з поверненням коштів. |
| 20 | Гість | Скасовано без повернення | End Event | При повному штрафі процес завершується без повернення коштів. |
| 21 | Гість | Отримано розрахунок скасування | Intermediate Message Event | Ловить повідомлення від кроку 7 (потік 27); далі шлюз 8. |
| 22 | Гість | Отримано результат скасування | Intermediate Message Event | Ловить повідомлення від кроку 18 (потік 31); далі кінцеві події 19 або 20. |
| 23 | Гість | Надіслати запит на скасування | User Task | Після події 1 гість надсилає запит (потік 26) до кроку 2. |
| 24 | Готель / Система | Скасування оброблено | End Event | Кінцева подія пулу «Готель». |
| 25 | Платіжний провайдер | Отримано запит на повернення | Message Start Event | Початкова подія пулу «Платіжний провайдер»; ловить потік 28. |
| 26 | Гість → Готель / Система | «Запит на скасування» | Message Flow | Від кроку 23 до кроку 2. |
| 27 | Готель / Система → Гість | «Розрахунок скасування» | Message Flow | Від кроку 7 до кроку 21. |
| 28 | Готель / Менеджер → Платіжний провайдер | «Запит на повернення коштів» | Message Flow | Від кроку 15 до кроку 25. |
| 29 | Платіжний провайдер → Готель / Менеджер | «Результат повернення» | Message Flow | Від кроку 30 до кроку 17. |
| 30 | Платіжний провайдер | Повернення виконано | Message End Event | Кидальна кінцева подія: надсилає результат (потік 29) до кроку 17. |
| 31 | Готель / Система → Гість | «Результат скасування» | Message Flow | Від кроку 18 до кроку 22. |
| 32 | Готель / Система | Бронювання | Data Object | Об'єкт даних; асоціації до кроків 2 і 12. |
| 33 | Готель / Система | Тарифи і політика скасування | Data Store | Сховище даних; асоціація до кроку 3. |
| 34 | Готель / Система | Анотація «F-110 і BL-60 суперечать щодо межі 5–6 днів до заїзду; рішення за замовником» | Text Annotation | Асоціація до кроку 3. |

**Примітка:**  
У SRS існує суперечність щодо межі безкоштовного скасування: F-110 вказує 5 і більше днів, а BL-60 — 7 і більше днів. До уточнення вимог BPMN має відображати три рівні штрафу без самостійного усунення цієї суперечності.

### Процес 4 — Обробка повідомлень гостей

**Учасники:**
- Гість
- Готель
  - Система
  - Адміністратор
  - Менеджер

**Тригер:** надіслано контактну форму з ім'ям, email, телефоном, темою та повідомленням.

**Кінцевий результат:**
- «Оброблено»

| № | Пул / доріжка | Крок | Тип BPMN | Опис |
|---|---|---|---|---|
| 1 | Гість | Виникло питання до готелю | Start Event | Початкова подія пулу «Гість». |
| 2 | Готель / Система | Зберегти повідомлення | Service Task | Система зберігає отримане повідомлення гостя. |
| 3 | Готель / Адміністратор | Переглянути повідомлення | User Task | Адміністратор читає повідомлення в адмінпанелі. |
| 4 | Готель / Адміністратор | Визначити тип питання | Exclusive Gateway (XOR) | Адміністратор визначає категорію звернення. |
| 5 | Готель / Адміністратор | Передати питання менеджеру | User Task | Якщо звернення стосується ціни або повернення коштів, адміністратор передає його менеджеру. |
| 6 | Готель / Адміністратор | Підготувати й надіслати відповідь самостійно | Send Task | Інші звернення адміністратор обробляє сам; відповідь іде гостю (потік 23) до кроку 16. |
| 7 | Готель / Менеджер | Підготувати відповідь | User Task | Менеджер формує відповідь на питання про ціни або повернення коштів. |
| 8 | Готель / Менеджер | Надіслати відповідь на email | Send Task | Відповідь іде гостю (потік 22) до кроку 16. |
| 9 | Готель / Менеджер | Минуло 24 години без відповіді | Boundary Timer Event (неперервний) | Прикріплено до задачі 7; спрацьовує, якщо відповідь не підготовлено за 24 години. |
| 10 | Готель / Система | Надіслати нагадування виконавцю | Service Task | Виконується гілкою події 9, не перериваючи підготовку відповіді. |
| 11 | Готель / Система | Нагадування надіслано | End Event | Власна кінцева подія гілки нагадування. |
| 12 | Готель / Адміністратор | Позначити повідомлення обробленим або видалити | User Task | Після відповіді повідомлення позначається як оброблене або видаляється. |
| 13 | Готель / Адміністратор | Повідомлення оброблено | End Event | Процес у пулі «Готель» завершується результатом «Оброблено». |
| 14 | Гість | Надіслати контактну форму | Send Task | Гість надсилає ім'я, email, телефон, тему й текст (потік 21) до кроку 15. |
| 15 | Готель / Система | Отримано повідомлення гостя | Message Start Event | Початкова подія пулу «Готель»; ловить потік 21; далі крок 2. |
| 16 | Гість | Отримано відповідь від готелю | Intermediate Message Event | Ловить потік 22 (від кроку 8) або потік 23 (від кроку 6). |
| 17 | Гість | Питання вирішено | End Event | Кінцева подія пулу «Гість». |
| 18 | Готель / Система | Повідомлення | Data Store | Сховище даних; асоціації до кроків 2 і 12. |
| 19 | Готель / Адміністратор | Звернення гостя | Data Object | Об'єкт даних; асоціації до кроків 3 і 7. |
| 20 | Готель / Менеджер | Анотація «Нагадування надсилається один раз; повторне звернення реєструється як нове» | Text Annotation | Асоціація до події 9. |
| 21 | Гість → Готель / Система | «Звернення гостя» | Message Flow | Від кроку 14 до кроку 15. |
| 22 | Готель / Менеджер → Гість | «Відповідь на звернення» | Message Flow | Від кроку 8 до кроку 16. |
| 23 | Готель / Адміністратор → Гість | «Відповідь на звернення» | Message Flow | Від кроку 6 до кроку 16. |
